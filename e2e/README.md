# Frontend parity tests

Playwright tests that record how the frontend behaves, so the Svelte rewrite (see `docs/svelte-migration.md`) can be checked against the current app one page at a time.

They never start uvicorn, never touch `data/board.db`, and never reach Claude or Prospeo. The frontend is served as static files, and a stateful mock in `support/mock-api.ts` answers every `/api/*` request from made-up fixtures.

## Run

```sh
cd e2e
npm ci
npx playwright install chromium   # once
npm test                          # about 25 seconds
```

- **Against the current frontend (the default):** Playwright serves `board/static` with `python3 -m http.server` on port 8781.
- **Against another build:** set `APP_URL`, e.g. `APP_URL=http://127.0.0.1:8766/next/ npm test`. No server is started; serve the build yourself. Every test opens pages relative to `APP_URL`, and `/api/*` is mocked on that origin.
- **One file or test:** `npx playwright test tests/people.spec.ts`, or add `-g "Rewrite"`.
- **Debugging:** `npm run test:headed`. For a failure, open the trace with `npx playwright show-trace test-results/<test>/trace.zip`.
- **Screenshots (optional):** `VISUAL=1 SHOTS=old npx playwright test tests/visual.spec.ts` saves every page at 1440 px and 400 px wide to `screenshots/old/`. Take a `new` set against the new build and compare them by eye. They are git-ignored.

## How the tests work

- **No real network.** `support/mock-api.ts` routes every request:
  - `/api/*` on the app's origin is answered by the mock.
  - The app's own files are served normally.
  - Google Fonts gets an empty stylesheet, and `img.fixture.test` (fixture logos) gets a tiny PNG, or a 404 for `missing.png`.
  - Anything else is blocked and fails the test, and so does an `/api/*` call the mock doesn't handle.
- **Uncaught page errors fail the test too.** The current app leaves failed requests in click handlers as unhandled rejections after showing a toast, so tests for those paths list the expected message in `api.allowedPageErrors`.
- **Frozen clock.** `Date.now()` is fixed at Wednesday 14 October 2026, 14:00 in Toronto (`support/clock.ts`), while timers run normally. Fixture timestamps are relative to it, so "2h ago", date groups, deadlines and "new since last visit" are stable. Tests run in `en-US` and `America/Toronto`.
- **Fixtures** (`fixtures/*.json`) are invented and follow the response shapes in `board/*.py`. **Never copy real data from `data/board.db` into them.** The Find People search links were generated by calling the pure `people.search_links()` function with made-up inputs.
- **Server state is mutable.** Each test gets a fresh `MockApi` (the `api` fixture). Writes change it, so a `PUT /api/tracker/…` shows up in the next `GET /api/tracker`. Tests can also change it before or after loading a page:
  - `api.tracker.items = []`, `api.account = fixture("prospeo-accounts.json").empty`, …
  - `api.on("POST", "/api/companies", detail(422, "…"))` answers one endpoint differently.
  - `api.hold("POST", "/api/refresh")` holds matching requests until the returned function is called, for checking busy states.
  - `api.jobOutcomes.outreach = { status: "error", error: "…", polls: 1 }` controls how an AI job ends, and after how many polls.
- **Request assertions.** Every API request is recorded with method, decoded path, query and parsed JSON body:
  - `api.calls()` and `api.last()` return recorded requests.
  - `api.listingQueries()` returns the board's `/api/listings` queries, without the new-since-visit count.
  - `api.jobRequests(kind)` returns `POST /api/ai/jobs` requests. Use it to check that Claude is only asked after a click.
- **Local storage.** `app.storage({...})` seeds `localStorage` before the first load only, so reloads see what the app stored. The keys in use are `filters`, `view`, `baseline`, `lastActive` and `toolListing`. `lastVisit` is legacy.
- **Replies wait for DOMContentLoaded.** The current `app.js` starts API calls before `features/*.js` run. A very fast reply can render the board before their hooks register (see "Known issues"), so the mock answers only once every script has run.

## Writing tests for the new frontend

- Prefer roles, labels and visible text: `getByRole("button", { name: "Track" })`.
- Some checks still use ids and classes, such as `#result-count`, `.fp-person`, `.docs-msg` or `#kanban .column[data-status=…]`, where the old markup gives nothing better. The new frontend should keep them, or the test should be updated in the same commit, with the reason in the commit message.
- Behaviour, copy and API calls must stay the same. If a test has to change because behaviour changes on purpose, say why in the commit.

## Known issues in the current app

These are documented, not fixed (step 0 changes no app behaviour). The tests marked `test.fixme` describe the intended behaviour and are skipped. Each was checked to fail against the current frontend. Switch them to `test` once the bug is fixed.

| Issue | Where | Test |
| --- | --- | --- |
| **Search again** and **Search Prospeo** on the Find People results page throw `search is not a function`. `renderResults()` declares a local `search` (the saved search) that shadows the `search()` function. | `features/people.js` | fixme: "Search again runs a new search for the same kind" |
| **The cover letter tone is never sent**, so every letter is formal. `select.js` copies the select's classes onto its wrapper `<span>`, so `querySelector(".docs-tone")` returns the wrapper, whose `.value` is `undefined`. | `select.js`, `features/documents.js` | fixme: "Write cover letter sends the tone picked in the dropdown" |
| After **Tailor resume**, the message reads "undefined ready. …". `writeDoc()` looks up `KIND_LABEL` by job kind (`tailor_resume`), but the labels are keyed `resume`. | `features/documents.js` | fixme: "Tailor resume finishes with 'Resume ready'" |

Not covered by a test, so the parity suite doesn't lock them in:

| Issue | Where |
| --- | --- |
| **Deadlines are off by a day around noon.** `deadlineInfo()` rounds the days left with `Math.round`. At 10:00, a deadline from yesterday shows "Due today", and one due today shows its date instead of "today". (Checked with the clock set to 10:00.) | `app.js` |
| **The skip link leaves the current page.** It sets the hash to `#main`, which the router treats as an unknown view and replaces with the board. | `index.html`, `app.js` |
| **Possible race on first load.** `app.js` starts API calls before `features/*.js` have run. A fast reply renders the board without match badges, and could leave the Find People page or the tracker panel sections missing until the next render. Seen in about 1 in 15 test runs before the mock waited for DOMContentLoaded. | `index.html`, `app.js` |
| **Intro draft progress never shows seconds.** The status line's `fp-draft-msg` class is replaced on the first update, and `onProgress` looks the element up by that class. | `features/people.js` |
| **Raw validation errors.** A one-letter name in "Add a person", a Prospeo key under 10 characters or with other symbols, and a company link under 3 characters all get FastAPI's list-shaped 422. The page then shows it as JSON text. | `app.js` `api()`, `features/people.js` |
| **"Delete saved contacts" has no confirmation.** It deletes every contact and search at once. Deleting a document asks first. | `features/people.js` |
| **No renewal date.** If Prospeo returns no renewal date, the out-of-credits message reads "…out of Prospeo credits until . …". | `features/people.js` |
| **Extraction polling.** `waitForExtraction()` has no time limit. Each visit to My profile while an extraction runs starts another polling loop. | `app.js` |
| **Re-check label.** After a failed Re-check, the button reads "Re-check" and loses "(free)" or "· 1 credit". | `features/people.js` |
| **Blank Find People page.** A `#people?listing=…` link with an empty tracker shows only the header. | `features/people.js` |
| **Lost panel edits.** A failed Save in the tracker panel still closes it, and the edits are lost (only a toast is shown). | `app.js` |
| **Root-relative links.** `/doc.html?id=…` and doc.html's Back (`/#tracker`) are root-relative, so they will point at the old app while the new one is served at `/next/`. | `features/documents.js`, `features/doc-page.js` |
