# Frontend browser tests

Playwright tests for the whole frontend. They were written against the old plain-JavaScript app as parity tests for the Svelte migration (see `docs/svelte-migration.md`), and now guard the Svelte app.

They never start uvicorn, never touch `data/board.db`, and never reach Claude or Prospeo. The built frontend is served as static files, and a stateful mock in `support/mock-api.ts` answers every `/api/*` request from made-up fixtures.

## Run

```sh
cd e2e
npm ci
npx playwright install chromium   # once
npm test                          # about 25 seconds
```

- **Default:** Playwright serves the build in `board/static` with `python3 -m http.server` on port 8781. Run `npm run build` in `frontend/` first, so you test your latest change.
- **Against another server:** set `APP_URL`, e.g. `APP_URL=http://127.0.0.1:5173/ npm test` for `npm run dev`. No server is started; serve the build yourself. Every test opens pages relative to `APP_URL`, and `/api/*` is mocked on that origin.
- **One file or test:** `npx playwright test tests/people.spec.ts`, or add `-g "Rewrite"`.
- **Debugging:** `npm run test:headed`. For a failure, open the trace with `npx playwright show-trace test-results/<test>/trace.zip`.
- **Screenshots (optional):** `VISUAL=1 SHOTS=old npx playwright test tests/visual.spec.ts` saves every page at 1440 px and 400 px wide to `screenshots/old/`. Take another set after a change (`SHOTS=new`) and compare them by eye. They are git-ignored.

## How the tests work

- **No real network.** `support/mock-api.ts` routes every request:
  - `/api/*` on the app's origin is answered by the mock.
  - The app's own files are served normally.
  - Google Fonts gets an empty stylesheet, and `img.fixture.test` (fixture logos) gets a tiny PNG, or a 404 for `missing.png`.
  - Anything else is blocked and fails the test, and so does an `/api/*` call the mock doesn't handle.
- **Uncaught page errors fail the test too.** A request that fails has already been shown in a toast, so the app marks it and doesn't let it surface as an uncaught error. If a test ever expects one, list it in `api.allowedPageErrors`.
- **Frozen clock.** `Date.now()` is fixed at Wednesday 14 October 2026, 14:00 in Toronto (`support/clock.ts`), while timers run normally. Fixture timestamps are relative to it, so "2h ago", date groups, deadlines and "new since last visit" are stable. Tests run in `en-US` and `America/Toronto`.
- **Fixtures** (`fixtures/*.json`) are invented and follow the response shapes in `board/*.py`. **Never copy real data from `data/board.db` into them.** The Find People search links were generated by calling the pure `people.search_links()` function with made-up inputs.
- **Server state is mutable.** Each test gets a fresh `MockApi` (the `api` fixture). Writes change it, so a `PUT /api/tracker/…` shows up in the next `GET /api/tracker`. Tests can also change it before or after loading a page:
  - `api.tracker.items = []`, `api.account = fixture("prospeo-accounts.json").empty`, …
  - `api.on("POST", "/api/companies", detail(422, "…"))` answers one endpoint differently.
  - `api.hold("POST", "/api/refresh")` holds matching requests until the returned function is called, for checking busy states.
  - `api.jobOutcomes.outreach = { status: "error", error: "…", polls: 1 }` controls how an AI job ends, and after how many polls.
- **Request assertions.** Every API request is recorded with method, decoded path, query and parsed JSON body:
  - `api.calls()` and `api.last()` return recorded requests.
  - `api.listingQueries()` returns the board's `/api/listings` queries, without the new-since-visit count.
  - `api.jobRequests(kind)` returns `POST /api/ai/jobs` requests. Use it to check that Claude is only asked after a click.
- **Local storage.** `app.storage({...})` seeds `localStorage` before the first load only, so reloads see what the app stored. The keys in use are `filters`, `view`, `baseline`, `lastActive` and `toolListing`. `lastVisit` is legacy.

## Writing tests for the new frontend

- Prefer roles, labels and visible text: `getByRole("button", { name: "Track" })`.
- Some checks still use ids and classes, such as `#result-count`, `.fp-person`, `.docs-msg` or `#kanban .column[data-status=…]`, where the old markup gives nothing better. The new frontend should keep them, or the test should be updated in the same commit, with the reason in the commit message.
- Behaviour, copy and API calls must stay the same. If a test has to change because behaviour changes on purpose, say why in the commit.

## Bugs fixed before the migration

Step 0 found these bugs in the old frontend. They were fixed before step 1, so the new frontend has correct behaviour to match. Each has a test.

- **Find People results:** **Search again** and **Search Prospeo** threw `search is not a function`. A local variable shadowed the `search()` function.
- **Cover letter tone:** the tone you picked was never sent. `select.js` copies a select's classes onto its wrapper, so `.docs-tone` matched the wrapper. The code now looks for `select.docs-tone`.
- **Tailor resume message:** it said "undefined ready. …".
- **Deadlines:** they were off by a day before noon. Days are now counted by calendar date.
- **Skip link:** it switched to the board. It now moves focus without changing the page.
- **First-load race:** `app.js` could render before `features/*.js` registered their hooks. It now starts on DOMContentLoaded.
- **Draft progress:** intro drafts never showed their seconds.
- **Raw validation errors:** these are now caught before sending (a one-letter name, an invalid Prospeo key, a link under 3 characters). Any list-shaped 422 that still reaches the page is shown as readable text.
- **Delete saved contacts:** it now asks first.
- **No renewal date:** the out-of-credits message no longer reads "until .".
- **Resume extraction:** it uses one polling loop per job, with a 10-minute limit.
- **Re-check label:** a failed Re-check keeps the button's full label.
- **Find People links:** a `#people?listing=…` link works with an empty tracker.
- **Tracker panel:** a failed Save keeps the panel open with your edits.
- **Document links:** the links to `doc.html` and its Back button are relative, so they work wherever the app is served.
- **Uncaught errors:** failed requests that were already shown in a toast no longer surface as uncaught errors.
